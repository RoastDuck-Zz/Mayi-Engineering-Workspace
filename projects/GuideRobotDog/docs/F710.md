# F710 控制（新版）

## 无终端开机待命

安装一次：`bash scripts/install-gamepad-service.sh --start`。
开机由 robotdog-gamepad.service 启动，读取 `/etc/robotdog-web.env` 的现有 PIN，不需终端输入。
后台启动不会自动连接、解锁或发运动请求：START 开始，BACK 解锁，Y 起立，X 行走。
B 急停并返回待命；再次操作先 START，再 BACK。后台进程持续等待按键，不关闭树莓派电源。
接收器缺失或移除时，服务每 3 秒重试；重新识别后仍回到待命。
控制模式独占输入设备，后台运行时不要再手动启动第二份控制程序。
查看状态：`systemctl status robotdog-gamepad`；日志：`journalctl -u robotdog-gamepad -f`。
维护停用：`sudo systemctl disable --now robotdog-gamepad`，运行中停用可能发送停止请求，应由操作者执行。

在项目根目录运行以下命令；手柄使用 X 模式，MODE 灯关闭。
输入检查：`.venv/bin/python gamepad.py`；控制：`.venv/bin/python -u gamepad.py --control`。
输入现有 Web PIN。程序启动不自动连接。

| 按键 | 功能 |
|---|---|
| START | 连接，最长等待 10 秒 |
| BACK | 解锁，仍不开放摇杆运动 |
| Y | 起立 |
| X | 行走；直接推摇杆移动，不需要 LB |
| A | 坐下 |
| B | 急停 |
| RB+Y | Bound 跳跃步态（不是单次定高跳） |
| RB+A | 双足倒立步态 |
| RB+X | 左侧翻请求 |
| RB+BACK | 右侧翻请求 |

组合键先按住 RB，再按另一键。动作需要已解锁、摇杆回中；按键只响应按下边沿。
特殊动作之后摇杆保持锁定，回中按 X 返回行走。是否支持完成相应动作取决于机器人固件，未进行实体动作测试。
左摇杆前后/横移，右摇杆转向；回中请求零速度。前后固定 ±0.25m/s，横移 0.25～0.30m/s，转向最大 0.5rad/s；死区 18%。

连接请求 10 秒、动作请求 3 秒、运动请求 200ms。请求完成后等待 50ms 再发送下一周期，实际频率随响应耗时下降。
非零摇杆连续无新输入 2 秒时锁定，回中按 X 恢复。回中原地等待不会锁定。固定非零摇杆也可能触发此保护；无法据此保证无线失联能立即识别。
服务端 Motion TTL 保留 300ms、控制权租约保留 3 秒。设备移除、输入事件丢失会退出并尝试停止。
HTTP 错误显示服务端具体原因并暂停运动，程序保留运行，等待人工重试，不自动重放动作。
START 先查询连接状态；后端重复连接请求复用现有连接，避免重复绑定 UDP 9873。
服务重启后需要先 START 再 BACK；未连接直接 BACK 会提示先连接机器人。

安装：`.venv/bin/python -m pip install -r requirements-gamepad.txt`。用户需要 input 组权限，加入后重新登录。
更新涉及 server.py：请用户在机器人停止并准备好后自行退出手柄程序、重启 robotdog-web 服务，再启动手柄程序。
服务重启会执行旧连接的停止、阻尼和断开，不应由助手远程执行。
